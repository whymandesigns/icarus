# pictogram

This skill makes **new** pictograms and illustrations that look like they belong to
Toptal's existing set: one colour, 1px strokes, a soft 15% tint. They are the larger
counterpart to the 16px icon sprite — if something reads at 16px, it is an icon.

Everything lives in designmd, and every path below is written from `designmd/`.
`<tool>` is `tools/pictogram.py`. One designer maintains this flow.

## The workspace

All work happens in **`pictograms/`** (its `README.md` has the layout):

- `explorations/<topic>/` — one folder per brief (`rob-meetings`, `initiatives`). Holds
  the candidates, the `ref-*.svg` library references for that brief, and a `notes.md`
  whose first line is the brief in one sentence (shown on the board).
- `approved/` — signed off. **Only move files here when the user approves them**, with
  `python3 <tool> approve <file>` (lints first, refuses on errors).
- `index.html` — the board: approved first, then every exploration as its own panel,
  rendered through designmd's real CSS. Rebuild it with `python3 <tool> board` after
  any change; never edit it by hand.

Start a new brief by making its topic folder and `notes.md`. Iterating on an existing
brief? Work in its folder and keep earlier candidates unless the user drops them — the
point of the board is comparing options. If a drawing is generated by a script, keep
the script beside the explorations (`explorations/gen-*.py`) so it can be re-run.

## The reference: the Figma library

[Pictograms](https://www.figma.com/design/6UPpJrQbP02OqBjtGL6KTr/Pictograms?node-id=3-10)
— file key `6UPpJrQbP02OqBjtGL6KTr`, page `3:10` — holds 317 pictograms, each a frame
named by keywords (`Search, magnifying, glass, research, analysis`) containing a
`Color=Blue` and a `Color=White` component. It is **context for the style**, not a
catalogue to pick from: the rules below were measured from it, and before drawing you
pull a few of its pictograms as references so a new one matches their proportions,
density and feel. designmd's `example.html` carries 13 more (`python3 <tool> list`).

## 1. Gather references

Pick two or three library pictograms close to what you're drawing — same kind of
object, same state, or same composition. Search by keyword with the Figma MCP
(`create_session`, then a read-only `use_figma`; load the `figma-use` skill first):

```js
const page = await figma.getNodeByIdAsync("3:10");
await figma.setCurrentPageAsync(page);
const q = ["calendar", "emptystate"];                // keywords, lower case
return page.children
  .filter(f => q.some(k => f.name.toLowerCase().includes(k)))
  .map(f => ({ name: f.name, blue: f.findOne(n => n.type === "COMPONENT" && n.name === "Color=Blue")?.id }));
```

The names are keyword lists, so search synonyms (`Box, Archive, Emptystate, backlog`).
Export each reference's Blue component and normalise it for the comparison sheet:

```js
const n = await figma.getNodeByIdAsync("<blue id>");
return await n.exportAsync({ format: "SVG_STRING" });
```

```bash
python3 <tool> import <raw.svg> --out pictograms/explorations/<topic>/ref-<name>.svg
```

`import` converts colours to `currentColor`, removes Figma's clip group and `<defs>`,
drops the fixed size and pins live strokes to 1px/butt/miter. Read the reference SVGs
too, not just their pictures — how they're built is the best guide to building yours.

If the Figma MCP isn't connected or authorised, say so and fall back to designmd's 13
(`python3 <tool> show <name>`) as references.

## 2. Draw

### The style, as measured from all 317

These numbers come from reading every Blue component in the library (Nov 2026).

- **Grid**: a 64×64 frame (310 of 317 exactly). The drawing **fills the frame edge to
  edge** on its long axis — 315 of 317 touch the frame. Use the space; don't inset.
- **128**: the library has no 128s. Draw at 128 only for a full-page empty state or
  onboarding, with the same 1px line and more detail, not heavier lines. Today
  `.pictogram` is a fixed 64px box, so a 128 ships shrunk to 64 until designmd adds a
  large modifier — tell the user, and don't add size CSS in the prototype (designmd
  rule 4).
- **Line**: **1px** (994 of 995 live strokes), **butt caps**, **miter joins**, centred.
  No round caps or joins, ever.
- **Colour**: lines are accent blue `#204ECF`; tints are a darker blue `#183A9E` at
  15%. designmd draws both as `currentColor` so a pictogram can be recoloured or
  muted — keep it that way.
- **Tint**: fill-only shapes at `opacity="0.15"` (830 of 836 tints; the rest are
  strays). Two patterns, both common: an **offset tint** — a band or shadow along one
  side of a shape, a lid, a header strip — or a **duplicate tint** — the same path as a
  stroked shape, filled (the check in a calendar, a pill in a box). One to three per
  drawing.
- **Density**: a median of ~11 shapes; most fall between 5 and 18. Up to ~70 at 128.
- **Construction in the library is mixed**: 196 of 317 were outline-expanded in Figma
  (strokes turned into filled shapes). **A new drawing uses real strokes** — the only
  full-opacity fills allowed are small solid dots (≤ 4px).

### Composition

- Build from primitives: rectangles (often with a small corner radius), straight lines,
  circles and arcs, a few simple curves. Flat, front-on or a light ¾ view.
- One clear subject plus **one storytelling detail** that says what's happening — rays
  over an archive box, a check on a calendar, a magnifier over a document, an alert
  mark. A literal object with no detail reads as an icon scaled up; this is the most
  common miss.
- Match your references' proportions and detail density, not just the rules above.
- Ideas that fit common states: empty → open/empty container; no results → magnifier
  over the object; nothing scheduled → calendar with a clock or a blank highlighted
  day; error → alert mark or a broken line; success → check; locked → padlock.
- **Overlaps**: with no fills behind lines and no masks, a line runs through any shape
  drawn over it. Where a badge overlaps the main object, stop the object's lines 2–3px
  short of the badge outline.
- At 64, nothing smaller than a 6×6 cell or closer than 4px apart — it turns to grey.
- Faces, hands, animals, organic shapes, lettering and logos don't work in this style.
  The library abstracts people as a circle head over a shoulder arc; follow that or say
  it needs an illustrator.

### Writing it

1. **Plan in words first**: each element with its coordinates (`body rect 1.5,7.5 →
   56.5,62.5`, `header line y=18.5`). Doing the arithmetic before writing paths keeps
   things aligned.
2. **Write the SVG** to `pictograms/explorations/<topic>/<name>.svg`. Name it
   for what it means, prefixed by the topic (`rob-weekly`, `init-launch`), never
   `ref-…` (that prefix marks library references). Skeleton — tints first so lines
   draw over them:

   ```svg
   <svg viewBox="0 0 64 64" fill="none" xmlns="http://www.w3.org/2000/svg">
     <path opacity="0.15" d="M57 11H7V20H57V11Z" fill="currentColor"/>
     <path d="M57.5 10.5H6.5V57.5H57.5V10.5Z" stroke="currentColor" stroke-width="1" stroke-linecap="butt" stroke-linejoin="miter" stroke-miterlimit="10" vector-effect="non-scaling-stroke"/>
   </svg>
   ```

   Every stroked element carries all six stroke attributes. Horizontal and vertical
   lines on half-pixel coordinates (`.5`) stay crisp at 1px; the library doesn't
   always do this, so the linter only warns.

## 3. Check

```bash
python3 <tool> lint pictograms/explorations/<topic>/*.svg   # refs will fail — expected
python3 <tool> board
```

Fix every lint error on your own drawings. Open the board in the browser pane — start
the `designmd` dev server (`.claude/launch.json`) and go to `/pictograms/index.html`. Each exploration is its own panel with its library
references beside the candidates, as shipped and muted. The references are the real
comparison: a new drawing should be hard to pick out from them. Match their density,
tint amount and use of the frame. Revise before showing the user.

`sheet` (ad-hoc, any files, `--section "<title>" <files…>` to group) is still there
for one-off comparisons outside the workspace.

## 4. Approve

When the user approves a candidate:

```bash
python3 <tool> approve pictograms/explorations/<topic>/<name>.svg [--as <final-name>]
```

It lints, moves the file into `approved/`, and rebuilds the board. Use `--as` to drop
an exploration-only suffix (`rob-weekly-v2` → `rob-weekly`). Never approve on your own
judgement, and never approve a `ref-*` file.

## Use

```html
<span class="pictogram is-filled"><svg viewBox="0 0 64 64" …>…</svg></span>
```

Prototypes take pictograms from `designmd/pictograms/approved/` only. `is-filled` is required:
it lets each path's own fill and stroke drive. Add `.is-muted`
for disabled or secondary states. Ignore the White variant — it's for dark surfaces,
and dark theme is parked (designmd rule 7).

## Traps

- **designmd's CSS re-weights any stroke that doesn't pin its own attributes.**
  `.pictogram.is-filled svg` sets `stroke-width: 1.5` and `.pictogram svg` sets round
  caps and joins. A path without its own values inherits them, so a raw Figma export
  pasted in renders at 1.5px with rounded ends. `import` and the skeleton pin them.
- **designmd's 13 are heavier than the library.** Six inherit 1.5px from the CSS above;
  the other seven were exported at 2× (128 grid, 3px strokes) and show at 1.5px in the
  64 box. The library is 1px. New pictograms are 1px by decision (Nov
  2026) — don't thicken them to match the 13, and don't re-weight the 13 as a side task.
- **Approving isn't adding to the showcase.** Approved pictograms live in
  `pictograms/approved/`. Putting one into `example.html` or the kit is a separate,
  deliberate change — don't do it as part of approving.
- **designmd deploys its whole folder** (`wrangler.jsonc`, assets `"."`), so
  `pictograms/` — explorations included — goes out with the next deploy.
- **Don't ship an edited library pictogram as a new one.** If a library pictogram is
  close, use it as a reference and draw the new one with real strokes; many library
  pieces are outline-expanded and would fail `lint`. If the user wants a library
  pictogram as-is, `import` it — that's fine, it just isn't this skill's job.
