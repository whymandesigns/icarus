Design Library

Master prompt

A copy-paste prompt for getting started with this project. Hand it to a coding agent (Claude Code, Cursor, …) and it scaffolds the skeleton of a new feature prototype on the Operationalize / Icarus design system.

How to use it

  1. Copy the prompt below.
  2. Replace {{FEATURE_NAME}} (kebab-case) and {{WHAT_IT_DOES}} with your feature.
  3. Paste it into your agent, run from the folder that contains designmd/ and features/ as siblings.
  4. Iterate locally, then inline + list it as the prompt describes.

The prompt

You are scaffolding a new feature prototype on the **Operationalize / Icarus design system**.

CONTEXT
- The design system lives in `designmd/`, a sibling of `features/`. It provides three
  stylesheets, loaded in order: `tokens.css` (primitives) -> `semantic.css` (intent
  aliases + reset) -> `components.css` (every component class). Plus `assets/logo.svg`
  and an icon sprite `icons.svg`.
- The complete, living component reference is `designmd/example.html` — open it to copy
  the exact markup for any component. Principles, color roles and rules are in
  `designmd/design.md`.
- Prototypes live at `features//index.html` — one folder per feature,
  kebab-case, the file is always named `index.html`.

TASK — create `features/{{FEATURE_NAME}}/index.html`
1. Start from this skeleton, linking the sibling system (keep these links while
   iterating locally for instant feedback):

2. Build the app shell: a `.topbar` (brand logo + search + avatar), a left `.sidenav`,
   and a main area with a `.page-head` (title + actions) above the content.
3. Compose the screen(s) for: {{WHAT_IT_DOES}}.

RULES
- Use ONLY semantic tokens and existing component classes — never hardcode a hex or px
  that a token covers. Colors: `var(--color-*)`. Spacing: `var(--ic-space-*)`.
  Type: `var(--type-*)`. Components: `.btn`, `.card`, `.table`, `.alert`, `.tabs`,
  `.page-head`, `.input`, `.badge`, etc. When unsure of a component's markup, read it
  from `designmd/example.html` rather than inventing classes.
- Icons come from the sprite: ``.
  Browse the names in the Iconography gallery in `designmd/example.html`.
- Keep it a single file. Do not add frameworks, build steps or external CDNs.
- Make it responsive and theme-aware (the system supports a `data-theme="dark"` toggle).

BEFORE SHARING / DEPLOYING
- From the `designmd/` folder run: `python3 inline.py ../features/{{FEATURE_NAME}}/index.html`
  to inline the whole system (zero external dependencies). It is idempotent.
- Add a card + a 1280x800 thumbnail for the feature to `features/index.html`.

FILL IN
- {{FEATURE_NAME}} — kebab-case folder name (e.g. `billing-portal`).
- {{WHAT_IT_DOES}} — one or two sentences describing the screen(s) to build.
