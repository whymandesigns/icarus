Component map

Goggles for the component kit. Turn them on and every component that has a React counterpart is outlined, with its Picasso import, resolved props and a Storybook link a hover away. The mapping lives in figma-map.json — the binding layer between this HTML/CSS library, the Figma Product Library and Picasso.

Kit only for now. The inspector runs in example.html, where the registry sits beside it. Prototypes carry the CSS but neither the script nor the registry, so ?map=1 does nothing there yet — see Taking it to prototypes.

Enable it

Open the kit with ?map=1, switch Component map on in the plugin launcher bottom-right, or press the goggles button in the kit's toolbar next to the theme toggle — all three do the same thing. Each flips the parameter and reloads, so the page always starts in a known state. Without it nothing is stamped, outlined or fetched.

example.html?map=1

What you get

Every mapped element picks up a dotted pink outline — deliberately off-brand, so it never reads as part of the UI being designed. Hovering one opens a popover with the cross-reference:

The JSX is not canned — it is built from the element in front of you. Each registry entry carries a propMap from designmd variant classes to Picasso props, so .btn-primary becomes variant="positive" and .accordion.is-open becomes expanded. Change the markup and the snippet changes with it.

Four more attributes annotate the foundations rather than components: data-picasso-color, data-picasso-font, data-picasso-radius and data-picasso-icon. These cross-reference the palette, type scale, radii and icon set against Picasso's Tailwind tokens, verified by value — so a shade with no Picasso equivalent stays unlinked rather than being given a plausible-looking one.

The registry

figma-map.json is the single source of truth; the inspector only renders what it finds there. Forty components are described today:

33mapped — clean 1:1
6partial — close, with caveats
1gap — no Picasso equivalent
34carry a Figma node id

A gap entry still earns its outline: hovering it says so in warning colour rather than staying silent, which is how the holes stay visible instead of being quietly forgotten.

Taking it to prototypes

The other two plugins reach prototypes: the review bar is baked in by inline.py, the states switcher is pasted in by hand. This one has not made that trip. What a prototype has today is the .map-* CSS, which rides along inside devtools.css — about fifteen inert rules, since nothing adds .is-map-mode and no script is present.

Three things would have to land for it to work there:

  1. Ship the script.Lift the inspector out of example.html's script block into its own map.js, the way review.js already is, so inline.py can bake it in and refresh it in place.
  2. Ship the registry.The script fetches ./figma-map.json relative to the page. A prototype would need it inlined, or fetched from a known path, rather than expecting a sibling file.
  3. Decide what gets stamped.Selectors are written against the kit's markup. A prototype composes the same components, so most should match — but that is an assumption worth testing on a real prototype before trusting it.

Until then the honest description is the one at the top of this page: a tool for the kit, used while mapping the library to Picasso — not something a reviewer opens on a prototype.
