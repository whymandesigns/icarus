Icarus Prototype Design System

An extension of Picasso, Toptal's production design system — its foundations as plain CSS. No React, no build step.

Browse and reference

Swatches, type scale, components, theme toggle.

Interaction patterns →

Documented interaction decisions with live playgrounds — when to use which pattern (e.g. confirm modal vs. undo toast for destructive actions).

DESIGN.md — the full written system →

Architecture, colour roles, typography, component shortcodes, workflow rules. About 16k tokens — read the section you need, not the file.

Master prompt →

Getting started — a copy-paste prompt that scaffolds the skeleton of a new feature project on this design system.

Plugin launcher →

The one button, bottom-right of every prototype, that switches the plugins below on and off. It lists what the page actually carries and greys out the rest, so there is one trigger to learn instead of three.

Plugin — Review bar →

Built into every prototype — comment on elements, retype copy in place, spotlight a region. Turn it on from the plugin launcher bottom-right or with ?review=1; comments land in feedback.json for an agent to apply.

Plugin — States switcher →

A floating panel bottom-left that jumps between a prototype's designed states (empty, loading, error, each flow step). Open with ?states=1, deep-link with &state=<key>. Copied into each prototype by hand; this page has the snippet.

Plugin — Versions & changes →

For features prototyped in several versions: ?versions=1 flips between them (state carries over, Alt+← / Alt+→), ?changes=1 outlines what's new, moved or changed vs the version before. Only on pages that declare <meta name="icarus-versions">.

Plugin — Component map →

Goggles for the component kit: outlines every component that has a React counterpart and shows its Picasso import, live JSX and Storybook link on hover. Open the kit with ?map=1. Reads data/figma-map.json; kit-only for now.

Feature prototypes →

One card per features/<name>/ folder. Only resolves inside Toptal's working layout, where features/ sits beside this folder — a standalone clone has no such directory.

Build with it

AGENTS.md — the rules →

Start here, human or agent. The rules, the traps and how to build and check a prototype, in about 1,300 tokens. Cursor, Copilot, Windsurf and Cline each get a generated copy at the path they look for.

llms-full.txt →

The rules, the worked markup, all 366 classes, 135 tokens and 369 icon slugs in one file, about 9k tokens. Paste it into a chat that cannot reach the repo. llms.txt is the short index.

dist/kit.json — the inventory →

Every class, grouped, plus the attribute-driven components, the behaviour hooks, and the showcase-only classes to reject. If a class is not in here it does not exist.
