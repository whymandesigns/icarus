Versions & changes

Two plugins for features that are prototyped in several versions side by side. Versions flips between them; Changes outlines what is new, moved or changed compared with the version before. Both sit in the plugin launcher and only exist on pages that belong to a versioned feature.

Enable it

On a version of a feature, open the plugin launcher (the button bottom-right) and switch on Versions and/or Changes, or add the parameters to the URL. Like every plugin, switching reloads the page so it starts clean.

…/features/initiatives/v3-breadcrumb/?versions=1
…/features/initiatives/v3-breadcrumb/?changes=1

They stack with the other plugins. ?states=1&state=create-blank&versions=1&changes=1 opens the blank create form with the versions panel and the change outlines, and switching versions keeps the same state, so you compare like with like. Alt+← / Alt+→ step through versions while the panel is on.

Only on versioned features. A page without <meta name="icarus-versions"> shows both plugins greyed out in the launcher — "Only on features prototyped in versions".

Set a feature up with versions

  1. One folder per version, inside the feature folder.features/<feature>/v1-<name>/index.html, v2-<name>/… Each is a frozen snapshot; a new version never changes an older one. Where a prototype moved, leave a redirect stub at its old path so shared links keep working.
  2. List them in features/<feature>/versions.json.Oldest first. basedOn names the version this one was copied from — it is what the Changes legend compares against.
  3. Declare the family in each version's <head>.That one tag is what switches both plugins on for the page.
  4. Run inline.py.versions.css / versions.js travel with the review bar and launcher, so every inlined prototype already carries them — dormant until the tag is there.
  5. Optionally, a landing page.features/<feature>/index.html listing the versions newest-first (see features/initiatives/).
{ "family": "Initiatives (TopTrack set-up / edit)", "versions": [ { "folder": "v1-drawer", "label": "v1 · Drawer", "date": "2026-10-01", "note": "Side-drawer create", "basedOn": null }, { "folder": "v2-full-screen", "label": "v2 · Full screen", "date": "2026-10-13", "note": "Full-page create with a TOC", "basedOn": "v1-drawer" } ] }
<meta name="icarus-versions" content="../versions.json" />

Mark the changes

Put two attributes on the element that changed — the row, card or section, not the input inside it (inputs can't carry the label). Keep the note to a few words; it is read at a glance.

<div class="in-form-row" data-change="moved" data-change-note="Stage tag → Status field">…</div>
  • Mark against basedOn only.A version shows what changed since the one it was copied from, not the whole history.
  • Starting a new version: clear the markers first.Copy the latest folder, remove every data-change / data-change-note, set basedOn, then mark as you go.
  • View mode and other states count too.Markers in rendered templates (drawers, view pages) work the same — they show whenever that state is on screen.
